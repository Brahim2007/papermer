## المرحلة 0 — قرارات تأطيرية (قبل أي كود)

| | المهمة | معيار الإنجاز |

| ☐ | **0.1** حسم مسار الورقة الأولى | وثيقة من صفحة واحدة تحدد: السؤال البحثي، الادعاء، المنفذ، جدول النتائج الرئيسي (فارغاً) |

## المرحلة 1 — البيانات (العائق الأول والأخطر)

### 1أ — التحقق الخارجي: أسرع طريق إلى أرقام قابلة للنشر

> **هذه أهم فكرة في القائمة كلها.** لا تنتظر التقييم البشري لتحصل على نتائج. المعايير المرجعية المنشورة تعطيك مدوّنة كبيرة + أحكام صلة جاهزة **فوراً**، وتتيح مقارنة أرقامك بأرقام منشورة. معيارك العربي يصبح عندئذ **المساهمة الجديدة فوق أساس متين**، لا البديل الوحيد عن الأدلة.

| | المهمة | معيار الإنجاز |
|---|---|---|
| ☑ | **1.1** مسح المعايير المرجعية المرشّحة والتحقق من التوفر والرخصة وحجم المدوّنة الفعلي | مكتمل في `docs/EXTERNAL_BENCHMARKS.md`: LitSearch أساسي، BEIR-SciDocs/SciFact حزمة التحقق الثانية، وMIRACL-ar اختبار سلامة لغوي |
| ☑ | **1.2** اختيار **معيارين** على الأقل واستيرادهما إلى صيغة المشروع (`corpus.csv` + `queries.jsonl` + `qrels.tsv`) | مكتمل: LitSearch + BEIR-SciDocs + BEIR-SciFact عبر `experiments/import_external_benchmark.py`، مع manifest وSHA-256 وسجل رخص |
| ◐ | **1.3** تشغيل مصفوفة B0–B7 كاملة على المعيارين | SciFact مكتمل (مع N/A المبررة للرسم)، وSciDocs مكتمل حتى B6؛ SciDocs-B7 وLitSearch-B2/B3/B5/B6/B7 ينتظران رفع Modal spend limit. الآثار وSHA-256 موثقة في `docs/EXTERNAL_MATRIX_RESULTS.md` |
| ☐ | **1.4** مقارنة أرقامك بالأرقام المنشورة لنفس المعيار | فقرة "sanity check" — إن انحرفت أرقامك كثيراً فلديك خطأ تنفيذي |

| المعيار | المجال | لماذا يناسبك |

| **LitSearch** | بحث أدبيات علمية، استعلامات واقعية | الأقرب لمهمتك بالضبط |

| **SciRepEval** | تمثيل الوثائق العلمية، مهام بحث وتوصية | تغطية واسعة |
| **BEIR / SciDocs / SciFact / TREC-COVID** | استرجاع علمي عام | مرجعية معروفة لكل محكّم |
| **MIRACL (الجزء العربي)** | استرجاع عربي عام | للتحقق من المشفّر متعدد اللغات **قبل** تطبيقه على مدوّنتك العلمية |

## المرحلة 2 — تحديث تقنيات الاسترجاع (جوهر الطلب)

> **لماذا هذه المرحلة ضرورية:** مصفوفتك الحالية B0–B7 هي سلّم الأسس المرجعية القياسي (BM25 1994، الاقتران الببليوغرافي 1963، RRF 2009، cross-encoder 2019، SPECTER2 2022). لا يوجد فيها ما يُقرأ كإسهام في 2026. الهدف هنا ليس اختراع خوارزمية، بل **رفع الأسس المرجعية إلى مستوى 2026** حتى تكون مقارناتك ذات معنى.

### 2أ — القناة الكثيفة: من مشفّر واحد إلى مقارنة أجيال

| | المهمة | معيار الإنجاز |
|---|---|---|
| ☐ | **2.1** إضافة مشفّر متعدد اللغات حديث — **`BAAI/bge-m3`** (المرشح الأول) | `retrieval/dense.py` عام بدل `specter2.py` المتخصص |
| ☐ | **2.2** إضافة مشفّر حديث ثانٍ للمقارنة (`intfloat/multilingual-e5-large` أو `Qwen/Qwen3-Embedding-0.6B` أو `jinaai/jina-embeddings-v3`) | تشغيلان مستقلان بمعرّفَي مراجعة مثبّتَين |
| ☐ | **2.3** **إبقاء SPECTER2** كأساس "متخصص في المجال" — لا تحذفه | يظهر في الجدول النهائي كـ B2 |
| ☐ | **2.4** تعميم واجهة الذاكرة المؤقتة لتقبل أي مشفّر | `specter_cache.py` ← `embedding_cache.py` مع حقل `model_id` في الميتاداتا |
| ☐ | **2.5** تثبيت مراجعة (commit hash) لكل نموذج جديد | مطابقة نمط `SPECTER2_BASE_REVISION` الموجود |

**لماذا BGE-M3 تحديداً هو المرشح الأول:**

| السبب | الأثر على مشروعك |
|---|---|
| متعدد اللغات (يشمل العربية) | **يفتح المرحلة 4 بأكملها** — بدونه لا مسار عربي |
| سياق طويل (8K رمز) | ملخص + عنوان + كلمات مفتاحية دون اقتطاع |
| يُخرج كثيفاً + متناثراً + متعدد المتجهات من نموذج واحد | يغطي المهام 2.6 و 2.9 معاً — اقتصاد كبير في الجهد |
| حجم معتدل | قابل للتشغيل على CPU بعد التكميم |

### 2ب — القناة المتناثرة المتعلَّمة (أكبر فجوة تقنية حالياً)

> BM25 وحده كقناة معجمية لم يعد كافياً كأساس مرجعي في 2026. التمثيل المتناثر المتعلَّم هو التطور المباشر لـ BM25 ويُتوقع وجوده في أي ورقة استرجاع محكّمة.

| | المهمة | معيار الإنجاز |
|---|---|---|
| ☐ | **2.6** تنفيذ قناة متناثرة متعلَّمة (SPLADE، أو رأس `sparse` في BGE-M3) | `retrieval/learned_sparse.py` + فهرس مقلوب |
| ☐ | **2.7** إضافتها للمصفوفة كـ **B1b** (نظير BM25) | مقارنة مباشرة BM25 ↔ متناثر متعلَّم على نفس الطيّات |
| ☐ | **2.8** إدراجها كقناة ثالثة في الدمج | تشغيل RRF: متناثر متعلَّم + كثيف + رسم بياني |

### 2ج — التفاعل المتأخر (Late Interaction)

| | المهمة | معيار الإنجاز |
|---|---|---|
| ☐ | **2.9** إضافة قناة ColBERT (رأس `colbert` في BGE-M3، أو نموذج ColBERT صغير مستقل) | `retrieval/late_interaction.py` |
| ☐ | **2.10** الإبلاغ عن تكلفة التخزين مقابل مكسب الجودة | جدول: حجم الفهرس (MB) ↔ nDCG@10 ↔ زمن الاستجابة |

> ColBERT مكلف تخزينياً (متجه لكل رمز). عند 50K وثيقة هذا معقول؛ **أبلغ عن التكلفة صراحةً** — هذا بالضبط نوع الأمانة الذي يميّز مشروعك.

## المرحلة 5 — LLM: من كناري إلى دراسة

> بياناتك الحالية في `llm_query_expansion_canary_v2_report.md` مثيرة أصلاً: زمن استجابة **×4.9** (742ms ← 3,655ms) مقابل تداخل 81% في أعلى 10 نتائج. أي: تكلفة كبيرة مقابل تغيير طفيف.

| | المهمة | معيار الإنجاز |
|---|---|---|
| ☐ | **5.1** إعادة تشغيل توسيع الاستعلام مقابل **أحكام صلة حقيقية** | nDCG/Recall فعلية بدل مقاييس التداخل |
| ☐ | **5.2** إضافة أشكال حديثة: تفكيك الاستعلام، الاسترجاع التكراري | أذرع تجريبية إضافية |
| ☐ | **5.3** **الإبقاء على المحاسبة الكاملة** للتكلفة والزمن والرموز | موجودة ✅ — لا تفقدها، هي ميزتك |
| ☐ | **5.4** **الحَكَم LLM مقابل المقيّم البشري** — أضف `assessor_llm` كمقيّم ثالث | `analyze_judgments.py` يحسب كابا تلقائياً — تغيير ضئيل جداً |

## قواعد لا تُخرَق أثناء التحديث

1. **لا تُحدَّث تقنية بحذف سابقتها.** SPECTER2 و BM25 و MiniLM تبقى كأسس مرجعية في الجدول النهائي.
2. **كل نموذج جديد = شرط تجريبي جديد** بمعرّف تشغيل جديد وذاكرة مؤقتة جديدة ومراجعة مثبّتة.
3. **لا تُقارَن تشغيلات عبر مدوّنات أو qrels أو حدود زمنية مختلفة.** `summarize_runs` يرفض ذلك أصلاً — لا تلتف عليه.
4. **قسم الاختبار لا يُلمس** حتى تجميد كل الإعدادات عبر `lock_development_runs`.
5. **لا يُعاد كتابة ملف نتائج استُخدم في ورقة.** استخدم معرّف تجربة جديداً.
6. **احتفظ بوسم "حدود التفسير"** في كل تقرير. هذه أقوى عادة في المشروع — لا تفقدها تحت ضغط الرغبة في نتيجة إيجابية.
7. **النتيجة السلبية نتيجة.** إن لم يتفوق التحديث على الأساس، أبلغ عن ذلك — مسارات الاستنساخ في المؤتمرات تقدّر هذا.
